# Cullen carbon dashboard (`carbon.ablz.au`)

**Status:** deployed 2026-09-29 on doc1 (`homelab.services.cullenCarbon`)
**Source:** `~/cullen-carbon/dashboard/index.html` on doc1 (repo
`git.ablz.au/abl030/cullen-carbon`), generated by `dashboard/build.py`

## Design

The dashboard is one self-contained HTML file that changes often, so it is
served live from the working checkout instead of being pinned as a flake
input. Regenerating or pulling `index.html` in `~/cullen-carbon` on doc1 is live
on the next page load (`Cache-Control: no-cache`). No rebuild and no
`nix flake update` is needed. Whatever is in the doc1 checkout is what is
served, including uncommitted edits. Edits made only in a worktree go live
once they are merged into the main checkout.

```text
browser → doc1 nginx :443 carbon.ablz.au (localProxy TLS/ACME, LAN DNS)
        → 127.0.0.1:8851 static server → /run/cullen-carbon-dashboard/index.html
```

nginx runs `ProtectHome=true` and `/home/abl030` is `0700`. Rather than widen
either, the module bind-mounts just `dashboard/` read-only into nginx's
namespace at `/run/cullen-carbon-dashboard`. It binds the directory, not the
file, because `build.py` and git replace `index.html` with a new inode. Only
`/` is served; `template.html`, `build.py` and anything else return 404. The
`-` prefix means a missing checkout does not stop nginx from starting; the Kuma
monitor `Cullen carbon dashboard` then fails instead.

If the whole `~/cullen-carbon/dashboard` directory is deleted and recreated
(not just its files), nginx still holds the old mount: run
`sudo systemctl restart nginx`.

## Cullen access

Cullen clients use the same split-horizon path as `bd.ablz.au`: a work-DNS
record `carbon.ablz.au A 192.168.100.128` → Windows :443 portproxy → WSL nginx
→ doc1. See [cullen-bd-split-dns](../infrastructure/cullen-bd-split-dns.md).
On WSL the hostname is in `cullenDoc1Hosts` in `hosts/wsl/configuration.nix`.
