# Brother scanner SMB compatibility share

**Date:** 2026-08-03 · **Status:** ✅ live on caddy LXC · **Module:** `modules/nixos/services/scanner-samba.nix`

The Brother printer/scanner is hardcoded to upload scans to:

```text
\\192.168.1.6\Scans
```

Tower's own SMB security policy is not compatible with the scanner. The retired
`Caddy2.0` VM therefore acted as a compatibility shim: it mounted tower's data and
re-exported only the scans directory with a standard standalone Samba server. This
service was missed when the old tower VM migrated to the NixOS caddy LXC (CT 108).
It was restored on 2026-07-26 without changing the scanner.

## Data path

```text
Brother scanner
  └─ SMB2: \\192.168.1.6\Scans
       └─ caddy LXC CT 108: /mnt/scans
            └─ prom bind mount (CT mp0):
                 /mnt/tower-scans
                      └─ NFSv4.2 from tower:
                           192.168.1.2:/mnt/user/data/Life/Meg and Andy/Scans
                           └─ same directory consumed independently by
                              doc2 Paperless at /mnt/data/Life/Meg and Andy/Scans
```

`prom` mounts the scan directory independently at `/mnt/tower-scans`. Do not
source this mp0 from the broader `/mnt/tower-data` mount: that mount is also used
by igpu CT 107, so scanner recovery would otherwise risk unrelated media work.
The persistent host entry in `/etc/fstab` is:

```text
192.168.1.2:/mnt/user/data/Life/Meg\040and\040Andy/Scans /mnt/tower-scans nfs4 rw,noatime,vers=4.2,hard,softreval,timeo=50,retrans=5,_netdev 0 0
```

The persistent Proxmox configuration is in `/etc/pve/lxc/108.conf`:

```text
mp0: /mnt/tower-scans,mp=/mnt/scans
```

This `mp0` entry is hand-managed Proxmox state; it is not generated by the Nix
flake. Verify it after restoring or recreating CT 108:

```bash
ssh root@prom 'pct config 108 | grep ^mp0:'
ssh root@prom 'findmnt /mnt/tower-scans'
ssh root@prom 'pct exec 108 -- /run/current-system/sw/bin/findmnt -T /mnt/scans'
```

## Samba policy and authentication

The declarative service is enabled by
`hosts/caddy/configuration-lxc.nix` as
`homelab.services.scannerSamba.enable = true`.

Security boundaries:

- Samba binds only to `lo` and caddy's LAN `eth0`.
- The firewall opens TCP 139/445 and UDP 137/138 only on `eth0`; SMB is not
  exposed on `tailscale0`.
- The only share is `Scans`, writable only by Samba user `abl030`.
- Guest access is not enabled. `map to guest = Bad User` matches the retired VM.
- The old `Scans2`/`MegScans` share was deliberately not restored; the Brother
  device uses only `Scans`.

The old Ubuntu Samba configuration and the new NixOS Samba 4.23 configuration
have the same effective compatibility settings:

```text
server min protocol = SMB2_02
server max protocol = SMB3
ntlm auth = ntlmv2-only
server signing = default
lanman auth = no
```

The scanner's saved username/password therefore continue to work. The original
Samba password database was migrated out-of-band from the retired VM to
`/var/lib/samba/private/passdb.tdb`; no password hash is stored in Git. A normal
NixOS deployment preserves this mutable state.

If the passdb is lost, either re-enter new credentials on the scanner and run
`smbpasswd -a abl030`, or recover the old database from the retired VM disk on
tower:

```text
/mnt/cache/domains/linux/20240707_0300_vdisk1.img
  /var/lib/samba/private/passdb.tdb
```

Mount the image read-only and keep the recovered TDB mode `0600 root:root`.
Never commit it or print its NT hash.

## Deployment and verification

Deploy from doc1 through the verified fleet path:

```bash
fleet-deploy caddy
```

Check the service and listener from prom/doc1:

```bash
ssh root@prom \
  'pct exec 108 -- /run/current-system/sw/bin/systemctl is-active samba-smbd samba-nmbd'
nc -zvw3 192.168.1.6 445
```

Check the effective configuration inside the LXC:

```bash
ssh root@prom \
  'pct exec 108 -- /run/current-system/sw/bin/testparm -s /etc/samba/smb.conf'
ssh root@prom \
  'pct exec 108 -- /run/current-system/sw/bin/pdbedit -L'
```

A complete acceptance test must authenticate as `abl030`, upload a uniquely named
temporary file through `//192.168.1.6/Scans`, compare it with the file under
`/mnt/scans`, and delete it again through SMB. The 2026-07-26 restoration passed
that write/read/delete test using the migrated credential without changing it.
The final user-level check is a real scan from the Brother panel.

## Failure isolation

- **Port 445 closed:** check `samba-smbd.service`, the caddy revision, listener
  binding, and the `eth0` firewall rules.
- **Authentication rejected:** confirm `pdbedit -L` contains `abl030`; do not
  weaken the share to guest access as a first response.
- **Upload connects but cannot write:** verify `/mnt/scans` is the NFS-backed mp0,
  tower's export is writable, and the destination directory still permits the
  all-squashed NFS identity.
- **`Stale file handle`:** this was the 2026-08-03 failure after tower's NFS
  service disappeared and returned. Confirm Samba logs show the stale handle,
  refresh only `/mnt/tower-scans` on prom, then reboot CT 108 so its mount
  namespace receives the new NFS mount object. Do not remount the broader
  `/mnt/tower-data`; igpu CT 107 also consumes it.
- **Files land locally instead of on tower:** stop Samba immediately and restore
  CT 108's `mp0`; `/mnt/scans` must never become an ordinary LXC-root directory.
- **Paperless does not consume a successful scan:** SMB is already healthy; trace
  doc2's independent `/mnt/data/Life/Meg and Andy/Scans` mount and
  `paperless-consume` service path.
